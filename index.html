1. Overview

Given an RGB-D image and a free-form natural language instruction, the pipeline:

  1. Sends the instruction to a local LLM (Mistral via Ollama) → concise visual keyword.
  2. Passes that keyword to YOLOE → pixel mask of the target object.
  3. Feeds RGB-D + mask to Any6D → 4×4 pose matrix relative to an anchor view.

Why it matters

  • No training on target objects.
  • No CAD model at inference time.
  • Natural language as the only user interface.

2. System Architecture

User instruction (natural language) │ ▼ ┌─────────────────────┐ │ LLM (Mistral) │ Ollama REST API · 172.18.0.1:11434 │ core/llm.py │ Extracts 1–3 word visual keyword └─────────┬───────────┘ │ keyword (e.g. "yellow mustard bottle") ▼ ┌─────────────────────┐ │ YOLOE Segmentation │ Open-vocabulary instance segmentation │ core/detection.py │ yoloe-26l-seg.pt · conf ≥ 0.1 └─────────┬───────────┘ │ binary pixel mask ▼ ┌─────────────────────┐ │ Any6D Registration │ Model-free 6D pose estimator │ estimater.py │ est.register(K, rgb, depth, ob_mask, iter=5) └─────────┬───────────┘ │ ▼ 4×4 SE(3) pose → result.json · pose_4x4.txt · viz_pipeline.png

Anchor correction (HO3D)

corrected_pose = (pred_query @ inv(pred_anchor)) @ gt_anchor

A reference anchor frame with known GT pose cancels systematic error when query and anchor views differ significantly.

12. LLM Keyword Calibration

YOLOE matching quality depends on keyword quality:

  • "can" → 0% detection (too generic)
  • "tin can" → better recall
  • "cylindrical steel can" → highest confidence

The CALIBRATED_SYSTEM prompt (1195 examples) teaches Mistral to produce YOLOE-friendly keywords for LINEMOD, YCB-Video, HOPE, HomebrewedDB, T-LESS, ITODD, ContactPose, HANDAL, NOCS, and robotic instructions.

13. Design Decisions & Limitations

LINEMOD detection

  • Plain white backgrounds confuse YOLOE (trained on natural scenes)
  • LLM often outputs single-word keywords despite examples
  • Fallback to GT mask keeps ADD valid; Det_Rate reflects real capability
